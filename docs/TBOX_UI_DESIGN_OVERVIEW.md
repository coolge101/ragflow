## 3. 设计原则（摘自参考与总纲）

1. **任务优先**：以 **检索 + 多轮对话** 为核心路径；文档上传、版本、审计为辅线；运营看板 **非 P0**（SpecStory 记录）。
2. **强权限**：登录后按 **细粒度 permission** 控制菜单与路由；无权限进入 **`/no-permission`** 类体验。
3. **单库心智**：导航中显式标注 **单知识库**（与参考布局 `kbName` 一致），避免用户误解多空间切换。
4. **视觉基调**：**科技感**，主色 **蓝**、辅助 **青绿**（见 `global.css` 变量）；表格 + 卡片后台风，可适度留白。
5. **语言**：**中文**为主（总纲 §7）。
6. **终端**：**桌面优先**，**平板 / 手机可读可操作**（总纲 §6 问卷：需兼顾移动端）。
7. **合规展示**：当前原则为 **可出域**、**不做脱敏展示**（SpecStory）；若后续变更，须先改总纲 §7 再改本文档。

## 4. 信息架构（一级）

与参考路由 **语义对齐**（名称以中文产品为准）：

| 模块 | 参考路径（Vue） | 核心权限（参考） | 说明 |
|------|-----------------|------------------|------|
| 对话 | `/` | `chat.use` | 多轮问答；流式 SSE（参考 `sseChat.ts`）；引用/高亮为 P0 增强项。 |
| 检索 | `/search` | `search.use` | 关键词 / 语义检索试用与片段预览。 |
| 文档 | `/documents` | `doc.view`（上传/删除等见详细设计权限表） | 列表、状态、版本与导入导出入口。 |
| 采集 | `/crawl` | `crawl.manage` | 网络爬取任务（壳页 → S4 对接）；见详细设计 §4。 |
| 知识库配置 | `/kb` | `kb.configure` | 单库配置；危险操作单独权限键（参考 `kb.dangerous`）。 |
| 审计 | `/audit` | `audit.read` | 日志与操作留痕。 |
| 用户与角色 | `/users` | `user.manage` | 与总纲「用户管理」对应。 |
| 登录 | `/login` | 公开 | 生产环境对接真实登录；参考为开发角色模拟。 |

**知识爬取管理**：主 fork 侧栏一级 **「采集」**（`/crawl`，`crawl.manage`），与详细设计 §4 方案 A 一致。
